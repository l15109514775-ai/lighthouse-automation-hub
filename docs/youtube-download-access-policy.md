# 下载访问保护与新服务器启用

### 2026-11-11 单场传输设置

FIFO V4 对选定的 HTTPS 音视频轨逐条下载。每轨最多两个范围请求同时读取，每个范围至多 10 MiB。主线程按文件偏移依次写入完整范围，已有连续的 `.part` 前缀可以续传。媒体请求及其重定向仍经过原有的请求间隔、预算和平台拒绝检查。

顶层 TOML 配置 `youtube_download_range_workers = 2` 与 `youtube_download_rate_bytes_per_second = 18750000` 对应单场合计 150 Mbps。两个读取线程和两个音视频轨共用一个计速器。该值计算媒体正文的应用层传输速率，协议开销、套接字缓冲和其他进程的流量会影响网卡读数。原有的视频重任务锁仍限制同时处理的回放数。

2026-11-10：按用户要求为迁移后的 V4 下载入口增加保守访问策略。当前生产下载服务保持停用。本变更不保证平台放行，不使用代理、账号轮换、IP 轮换或请求指纹伪装。

## 保留的现有行为

- 频道发现和直播状态继续通过官方 Data API，保存观察结果；下载器不扫描整个频道。现有 300 秒官方来源新鲜度检查不放宽。
- FIFO 只接受已结束、符合授权和运营日期范围的回放；目标素材尚未就绪时沿用每 900 秒一次、有截止时间和次数上限的 readiness 检查。
- 全部视频重任务共用原视频锁；音视频顺序下载，分片并发 1。内部请求重试保持 0，由任务队列负责有限重试。
- 继续使用现有只读授权会话；没有自动登录、自动切换账号或从其他机器同步 Cookie。当前政策要求认证会话，不能把缺少会话悄悄解释为匿名授权。
- 继续保留 partial 文件、租约、请求预算、FFprobe、哈希与交付验证。下载入口不包含发布处理器。

## 本次增加

迁移 `018_youtube_acquisition_access.sql` 在原 `hub.sqlite3` 新建单行状态表，不改已有 jobs、publication、attempts 或幂等关系。

V4 子进程在每次媒体/网页 HTTP 请求（包括重定向）前通过共享 SQLite 预留请求时间；等待在事务外完成，等待期间持续检查租约、绑定与磁盘。两个进程共用同一请求间隔，不将暂停状态放在 Python 内存中。

| 设置 | 默认值 |
| --- | --- |
| 元数据请求预留间隔 | 1 秒 |
| 媒体请求预留间隔 | 0.25 秒 |
| 一次整场下载处理结束后，到下一任务的间隔 | 60 秒 |
| 429 最短冷却 | 3600 秒；有效 Retry-After 更长时遵守更长值 |
| 普通网络失败等待 | 60、120、240 秒，最高 3600 秒 |
| 普通网络失败最大任务尝试数 | 3，并仍受已有 max_attempts 约束 |

这些是保守的工程默认值，不是 YouTube 公布的安全阈值。`config/hub.example.toml` 的 `[youtube_acquisition_access]` 可调，不能用零值或 disable 开关关闭保护。

401/403、429、播放器明确拒绝及会话失效会持久化全局人工暂停、稳定错误码、事件与审计记录。传输层收到拒绝即写入数据库，因此子进程随后崩溃或未写出结果文件，也不会让下一任务继续访问。

暂停时不认领 V4 任务，不消耗待处理任务的 attempts；本地来源登记和心跳继续。发布和官方 API 监控不受本下载暂停替代或控制。429 冷却时间到期也不会自动恢复，须维护人员核查。普通网络错误只延后并有限重试，不自动清除其他原因造成的暂停。

## 状态与受控恢复

在新镜像、正确配置和已迁移数据库的环境中：

```bash
python -m services.hub.youtube_access status
python -m services.hub.youtube_access resume --revision <status中显示的revision>
```

恢复命令要求交互输入现有维护令牌（不放命令参数、不输出），核对状态版本，并拒绝提前结束 Retry-After 等待。只读令牌不能恢复。恢复只解除下载入口暂停，不修改任何任务的状态、attempts 或发布记录；被拒绝的那条任务仍须另行核查，不自动重排。

## 新服务器迁移顺序

1. 保持下载 profile 关闭，构建包含本提交、现有锁定依赖和子模块的新镜像；不能直接使用此前合格的旧候选镜像。
2. 对原数据库做一致性备份，将同一份数据库迁移到新主机；不建第二套任务数据库，不清空访问限制状态。
3. 用新镜像的既有 `python -m services.hub.cli init` 执行幂等迁移（先停下载，保留备份），然后运行 `python -m services.hub.acquisition_preflight`。检查必须显示访问保护表存在、配置合法；人工暂停会显示明确 blocker。
4. 确认只有一个采集入口。旧 V1/V2/V3 独立维护脚本不受新 V4 保护器覆盖，不得并行运行；它们不得作为平台拒绝后的备用入口。
5. 完成新主机权限、磁盘、SQLite、锁、重启恢复验收。通过正规登录或平台验证处理必要授权，不能通过删表、换账号或轮换 IP 清除限制。
6. 只放行一条获授权短回放验收，再验收一条长回放。合格后才按 FIFO 逐条放行新任务。出现拒绝即停止真实测试，保留证据，不继续换样本请求。

当前未执行以上生产迁移或真实下载。旧服务器的下载服务、账号会话、任务数据库和运营配置均不因源码更新而启用。

## 回滚

先停止新下载容器，保留 SQLite、partial 文件、访问暂停表和任务记录。可回退源代码或镜像供离线排查，但旧镜像没有此保护，不能以回退为由恢复自动下载。无需删除新增表，也不恢复旧数据库覆盖期间产生的任务数据。修复并重新验收后再启用。
