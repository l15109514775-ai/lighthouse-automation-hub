# 减配版：单台海外服务器部署规划

本方案以降低小团队月度支出为目标，不改变现有默认部署。预算见 [README](../README.md)。

## 目标与当前边界

目标是把网站后端、QQ bot、X 自动转推、YouTube 回放中枢集中到一台海外服务器，并用家用设备保存冷备。地区选择还应符合服务商与各平台规则，提前测试 QQ 接入、下载和投稿的稳定性。

当前中枢使用 SQLite，可独立运行；协作平台使用 CloudBase PostgreSQL、身份认证、RPC gateway 与存储。**把数据库复制到本地 PostgreSQL 并不等于完成脱离 CloudBase 的迁移。** 本次只新增方案文档，没有实现替代后端、修改部署配置或验证生产迁移。

| 层次 | 规划 | 必须验证 |
| --- | --- | --- |
| 网站 | 静态文件由 HTTPS 反向代理提供 | 登录、会话、验证码、跨域/CSP 与权限 |
| 协作后端 | 自托管 PostgreSQL + 鉴权/RPC 服务 | SQL 兼容性、用户身份映射、角色与行级权限、审计 |
| 上传与交付物 | 自托管文件服务或独立对象存储 | 签名上传/下载、权限、配额、保留与恢复 |
| QQ bot | 与中枢同机但独立进程/容器 | 使用受支持的 QQ 接入方式；保留 RPC 权限边界，不直连管理员数据库 |
| 推文与回放 | 复用现有中枢，限制并发 | 去重、重启恢复、投稿回写、磁盘水位 |
| 语音识别 | 千问 ASR 按需使用；或已有家用设备跑 Whisper | 真实音频吞吐、等待时间、隐私与预算 |
| 备份 | 家用设备定期拉取并离线保留 | 数据一致性、加密、版本保留与恢复演练 |

## 资源取舍

- 2 核 4G 是预算起点，不是容量保证。数据库、bot、图片渲染、下载/合并争用 CPU、内存和磁盘，建议先串行处理重任务，再按监控调整。
- 不把长录播本地 Whisper 识别当作小云服务器的默认工作。即使没有 API 费用，也可能需要远超音频时长的计算时间。
- 4 核 8G 增加余量，但不保证满足所有回放并发。先测量峰值内存、转码耗时、吞吐和出站流量。
- 系统盘只放系统与代码。媒体空间至少按最大单场源文件、分段/合并临时文件及安全余量估算；空间不足时暂停领取新重任务，不盲目删除素材。
- 上传成功、服务器记录成功与平台可访问是不同状态。清理策略应等待所需的平台核验与备份校验，并保留失败恢复路径。

## 单机必须保留的安全措施

1. 仅公开必要的 HTTPS 入口；SSH 限制来源或走受控管理通道。数据库、队列、bot 管理面板和内部 API 只绑定本机/私有容器网络。
2. 服务分容器或独立低权限账号运行；数据库与 RPC 按角色授予最小权限。bot 和浏览器不持有数据库管理员凭据。
3. 密钥、Cookie、令牌和真实配置不进入 Git；使用受限权限的配置文件或密钥管理，日志脱敏并限制读取。
4. 对登录、RPC、上传设置鉴权、限流、大小限制与超时；不要因为“只有小团队使用”就取消权限检查。
5. 保持安全更新，设置进程自动恢复、资源上限与日志轮转；监测磁盘、内存、队列滞留和异常调用。
6. 冷备必须位于另一台设备，并采用独立受限账号。保存数据库一致性备份、交付物、配置及版本清单，加密敏感数据；不能只拷贝正在写入的数据库文件。
7. 定期实际恢复到隔离环境，验证能登录、查任务、读交付物；记录恢复点与恢复耗时。家用设备断电/离线会延迟备份，单机没有自动容灾能力。

## 上线前验收

- 在隔离测试环境验证注册/登录、权限拒绝、项目/任务/审核、QQ 绑定与通知、文件交付、审计和数据恢复。
- 自动化中枢先保留现有 `DRY_RUN` 与禁用发布开关，用合成数据验证去重和任务恢复。
- 迁移前完成可恢复备份；制定停写、切换、核验和回滚步骤，避免两套后端同时写入造成分叉。
- 确认各模型、X API 和存储的真实计费口径；免费额度到期或用完之后仍要有费用上限与停用策略。
- 在明确批准生产迁移后再切换真实域名、账号与任务；确认稳定、恢复验证通过后再决定是否退订旧资源。
