## 准备阶段发现的问题

1. 最初构建直接引用镜像 ID 的写法被构建器解释为仓库名，构建失败；改用本机基底别名，未拉取替代生产基底。
2. 旧推文镜像已有 497 层，增加三个层的候选触及 overlayfs 层数上限，未能启动。最终用单层安装变更，候选正常启动。未来迁移服务器时应从源码重新构建干净镜像，不能持续叠加补丁层。
3. 首次部署脚本把队列锁目录当作锁文件，切换前即失败，没有修改生产配置。核对现网锁实现后改为 `observer.lock`，随后两次切换均成功。

以上失败未被计为通过，失败候选未投入生产。
