## 已完成：部署入口与 Worker 边界

- 正常 CLI Worker 在构造处理器前选择 tweet / video / system 队列；其他队列的业务处理器不再连带构造。原有 `runtime(settings, store)` 联集调用保留给明确的旧入口，任务类型和状态没有改名。
- 字幕 poller 的服务配置和代码默认值均为 1800 秒，允许运维覆盖；安装示例将两个脚本分别安装为 unit 使用的 `poll.py` 和 poller 使用的 `fetch.py`。
- 部署生成器补上 `runner/`，两个取材端脚本使用部署者填写的网关，不再把原环境地址当作新部署默认值。
- 首页、架构说明及从零搭建主流程改为自托管 API Worker；保留仍被使用的 `st_cloud_*` 数据库接口名。

验证：隔离 Linux 容器中 68 项测试通过（真实临时 SQLite、处理器隔离、推文采集队列、发布后状态检查、poller 默认/覆盖）；配置生成器 4 项本地测试通过。Linux 测试无网络、无真实凭据、无生产挂载。Windows 初次扩大选择出现 3 个原生媒体校验失败，Linux 同选择全部通过；不把 Windows 失败计为通过。另一次测试因临时目录父目录未建立而未能运行，修正测试环境后重跑。
